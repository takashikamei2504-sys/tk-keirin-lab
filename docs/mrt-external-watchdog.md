# External MRT watchdog

Existing 04/34 minute cron remains the primary trigger. Successful main runs of measured S counts, LAB LINE freezing and frozen-outcome collection are secondary triggers with the existing freshness gate. An independent hourly ChatGPT task can use the authenticated GitHub connector to read runtime_status.json and the main Actions runs, then update only ops/mrt-watchdog.json if the runtime is stale (45 minutes) or degraded (15 minutes) and no recent live run exists. Use a commit message beginning "MRT-WATCHDOG: ". The marker is inert data and never enters a model. The push triggers the same coordinated MRT workflow; it rechecks freshness after obtaining the shared lock, so recovery is a no-op if another run already succeeded. The regular push of a code change or manual dispatch remains unconditional. No new Railway service, token, odds access, model updates or historical backfill. The hourly task is a best-effort independent fallback, not a 30-minute SLA; GitHub runner or connector outages still prevent execution. Only commit the marker when necessary, and verify outcomes rather than assuming success. Disable the task to stop external recovery.
