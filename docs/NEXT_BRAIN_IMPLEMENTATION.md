## 目標と現状の差

展開名を増やすだけでなく、選手の判断→相手の反応→位置・消耗の変化→次の判断を順番に生成する。追走離れからの再自力は候補の一つで、必須の筋にはしない。

## 判断と反応の仕様

1. `context(state, actor, race, memory)` で局面、ライン内の役割、前後の相手、圧力、残る仕掛け機会、仮説上の消耗、判明している進路を読む。
2. `propose(context)` は `key/actor/action/target/weight/basis` を返す。前受け、突っ張り、引き、抑え、カマシ、捲り、追走、切替、位置維持、番手利用、再仕掛け、追込み、単騎の追上げ等を条件で選ぶ。待機も通常の候補にする。
3. 相手の反応をその後の節として生成する。たとえば4の上昇に1が突っ張れば消耗と隊列を更新し、7の仕掛け余地を再評価する。1が引けば4の主導権を更新し、1の捲り返しは次の判断で検討する。
4. 行動と結果を分ける。カマシを選んだことと先頭奪取は別の節。追走失敗も意思決定とは別の結果として記録する。
5. `transition` は経過時間・位置移動・消耗の根拠を残す。短時間の連続行動には上限を設け、同じ状態で反応が循環しないようイベント番号を持つ。周回→打鐘→最終ホーム→最終バック→直線の順序を戻さない。

## 状態と成立判定

準備済みの `contracts.cjs` は局面、隊列、全員の仮説上のenergy、距離・速度・風の明示的な欠損を検査する。これは物理モデルではない。次の実装で `elapsedMs/lanes/gaps/routeAvailability/assumptionRefs` を追加する。

- `energy` は未校正の内部仮説値であり実測体力ではない。
- 距離・速度・風は不明なら `null`。仮定した数値を入れる際は `kinematicsBasis: rule_assumption` とルールの根拠を保存する。実測がなければ `measured` にしない。
- 成立判定は `allowed/blocked/unknown`。判明している矛盾だけを除外し、欠損から不可能を断定しない。不明な進路や速度で到達可能性を確定しない。
- 追走離れ後の空き番手は近さ・進路・移動の順序を確認する。後方の選手を一度の並べ替えで先頭へ動かさない。
- 位置・タイミングの詳細がない初期版は、到達を仮定した分岐を `unknown` と理由付きで残す。可能と確認できた分岐と区別する。

## 分岐の重み

準備済みの `weights.cjs:allocate(parentMass, candidates)` を各行動・反応・結果・2着／3着の節で使う。

- 重みは相対的な仮説配分。正の候補を兄弟間で正規化し、親の重みを保存する。
- `key` は説明文ではなく、同じ状態・同じ判断者に対する行動と対象の意味的な識別子。同じ候補を二度発見しても一度だけ数える。重みや成立判定が矛盾する重複はエラーにする。
- 異なる到達経路を持つ状態の統合では、それぞれから流入した重みを加算する。同じ候補の重複除去と混同しない。
- 全候補が不可／重みゼロなら `unresolvedMass` に残す。合法な待機や着順を捏造しない。
- 探索幅・深さの上限で打ち切る場合も未解決量を記録する。部分集合を全体100%に見せない。初期予算は幅64・深さ24を仮置きし、端末で調整する。
- 全終端で同一3連単を集計後、現行同様に上位と別筋から20点を選ぶ。経路数を単純な加点にしない。候補数20未満・入力不整合はエラー表示にし架空の買い目で埋めない。

## 条件別の記憶と自動収集

既存の全S級名簿・近況・6媒体の公開本文収集を再利用する。データを増やすだけで全員の性格が分かるとは扱わない。

| 種別 | 用途 | 有効範囲 |
|---|---|---|
| `habitual_observation` | 実際の走りの観察を条件別に集約 | 選手、相手の状況、局面。独立した複数根拠・経年減衰を持つ |
| `race_intention` | 「今日は前で」等の意向 | 対象レースだけ。実行済み行動の証拠にしない |
| `current_form` | 調子や近況の観測 | 出典の対象期間と失効時刻。恒常特性に混ぜない |

準備済み `eligibleMemory` は種別・範囲・出典・公開／取得時刻を検査する。話者帰属や本文の事実確認を代行するものではない。既存の本文照合を通った短い観察を別の変換層から渡す。登録番号と氏名を照合し、公開・初回取得がともに発走前、かつ有効期限内の資料のみ利用する。欠損B/Sはゼロにしない。現在の少数の行動根拠を意向コメントで水増ししない。

## キーマンと確認方法

キーマンは同じ判断直前の状態から行動だけを変えて下流の反応を再生成し、1着分布・展開・20点がどの程度変わるかを比較する。相手の反応や主導権の結果を固定して効果を消さない。未解決量が異なる比較は併記する。

```sh
npm run prepare:next-brain
npm test
node tests/recent-form.test.js
```

`fixtures.json` は架空ケース3件（9車の前二線の攻防、7車の進路制約、追走喪失後の複数反応）。準備チェックは入力と重み部品の整合性だけを確認する。各ケースの `acceptance` は次期本体の受入条件であり、現時点でその推論を通過したという意味ではない。各段階で条件を実際の出力アサーションへ変換する。

公開前には現行と同じ出走表で比較し、欠損あり／記事なし／発走後資料の除外、候補重複で不変、全員の隊列・着順の整合、20点と経路の対応、390px画面・コピー・JSON保存を確認する。精度評価では予想生成時点のデータを固定し、後知恵による再現と区別する。
