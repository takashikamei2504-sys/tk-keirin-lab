# TK KEIRIN LAB B-AXIS v0.2 — Bを軸とする6局面展開推理

## プロジェクトの原則
指定選手が最終Bの先頭であること**だけ**を強制条件とする。その選手・所属ラインの入着は必要条件としない。B固定から全選手の位置・仕掛け・追走関係・消耗を再構築し、その条件での着順を評価する。

## 追加した予測フロー
入力（発走前の並び・脚質・得点・B/S本数・近況・コメント）→
B獲得候補選択／ユーザーB手動指定 → 戦法選択 → **6局面展開** → B時点の全選手の状態 → B後の複数の着順経路 → 1〜10点の三連単。

6局面を次の順に構築する。①初手・前受け、②赤板〜打鐘、③最終ホーム、④最終バック、⑤3〜4コーナー、⑥直線ゴール。
- 初手はライン全体のS傾向・先行傾向・戦術を考慮して仮置きする。後位選手のB獲得は、序盤から勝手に先頭扱いせず、元ライン先頭からの発進・交代を明示する。
- 赤板〜打鐘は、前受け突っ張り・押さえ先行・捲り準備などを記録。捲りは後方から一局面で複数ラインを飛び越えない。
- 最終ホームはカマシ／捲りの仕掛け、他線の抵抗、番手・3番手の発進、単騎の位置取りを検討する。
- 最終バックはユーザー指定のBを先頭とし、他線自力の外攻撃、元先頭の切替、後続の追走・離れ、全選手の相対消耗・残脚を引き継ぐ。
- 3〜4コーナーは、B番手差し、牽制成功・失敗、別線自力の外捲り、B側3番手の内進路、別線番手の進出を決着経路別に説明する。
- 直線ゴールは、上位三連単の1・2・3着と全選手の順位を同じ展開図に表示する。

## 監査条件
- 7車・9車・全出走選手・手動B指定・選択可能な全戦法で重複・消失を禁止。
- B先頭の番号・位置を最終バックで保証し、それ以前の主導権変更に「カマシ／捲り／番手発進」等の経路を要求。
- 全局面で累積消耗の減少を禁止。位置・消耗は相対モデル値であり、実測秒数・車間・出力ではない。
- 1局面で3つ以上のラインを飛び越える無説明の位置変化を拒否。
- 3〜4コーナー／直線でBの勝利を固定せず、別線上位独占の可能性を維持。
- UIの手動B／戦法変更時に全6局面・全買い目を再計算する。

## 実装ファイル
- `js/b-axis/phases.js` — 独立した6局面生成・累積努力・監査
- `js/b-axis/engine.js` — B-AXIS v0.2に接続し、B時点の全員の状態から独立した決着経路を評価
- `js/b-axis/app.js` と `b-axis.html`, `css/b-axis.css` — iPhone操作画面の6局面表示
- `tests/b-axis-phases.test.cjs` — 7/9車の全選手B指定と選択可能戦法の総当たり回帰テスト
- `.github/workflows/b-axis-fast.yml` — 独立エンジンの高速回帰検査

## 次期への持ち越し
- バンク別の直線長、風向、同一選手の実測B・追走・4角位置による確率校正
- 本人コメントの戦法意図、ライン間の駆け引き・牽制成功／失敗の定量蓄積
- 最終B実測選手を用いたオラクルB検証と、事前に選んだBによる通常運用検証の分離
- 三連単3/5/8/10点の実測捕捉率と、取得時刻のあるオッズによる期待回収率検証
- 静的な戦術的・相対位置のヒューリスティックの限界（実測速度・相対時間・踏み出しの厳密な物理計算ではない）。物理監査を通ったとしても実戦での妥当性を保証しない。
