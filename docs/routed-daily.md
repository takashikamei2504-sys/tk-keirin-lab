# レース別自動予想の前向き評価

`routed-results.html` に自動保存の稼働状況・累積成績・日別／エンジン別／級班と車立て別／モデルと選択ルール別の成績を表示する。

GitHub Actions `Save and evaluate race-routed forecasts` は毎時08・28・48分に発走前予想を保存する。当日結果と過去分の照合は日本時間18:08・翌0:28・翌5:28以降の最初の定期実行が担当する（GitHub Actions の実行時刻は保証されない）。対象時刻の実行が飛んでも、次の定期実行で未完了枠を拾う。結果配信が遅い場合は、同一の照合枠を **60分以上の間隔を空けて** 自動再試行する。全レース終了を待つのではなく、その時点で終了から45分以上経った保存予想について、結果・払戻・識別子・ハッシュの評価が済むまで枠を完了にしない。配信日時だけが新しくなっても、結果待ちや払戻待ちがあれば完了扱いにしない。古いデータや配信取得エラーも完了として扱わない。手動実行では予想保存と結果照合を両方行い、訂正後の払戻も再評価できる。`scripts/routed-daily.cjs` が当日の男子7車・9車を全件処理する。ガールズ・その他の車立ては既存の対象範囲外。級班や並びを取得できないレースはエラーとして可視化し、後続実行で再試行する。GitHub側の遅延・停止時に定刻実行は保証されない。

自動選択は `js/routing/policy.js` の固定ルールを使用し、ブラウザと同じ `Router.build` と情報パックで買い目を生成する。各レースの最初の発走前予想を `data/routed_history/YYYY-MM-DD/<race_id SHA256>.json` に排他的に作成。エンジン・選択ルール・入力／出力ハッシュ・情報時点・保存時刻・入力・買い目・根拠を保持し、以後の実行では再計算も上書きもしない。高負荷の探索は1レース60秒で打ち切り、他レースを継続する。翌日分や発走済みレースへ予想を遡及追加しない。

結果は `results.json`、対象一覧と保存状況は `coverage.json` に分離。保存記録のある直近8日と古い結果待ち（1回最大24日）を再取得して訂正も反映する。買い目のハッシュ、発走前の時刻、出走者と発走時刻の一致を検証し、三連単1点100円・最大8点で的中と払戻を評価。同着は各有効組合せの払戻を合算する。払戻欠落は払戻待ち、中止・返還の明示は除外として扱う。配信が中止等を示さない場合、結果なしは結果待ちに残る。未保存・結果待ち・払戻待ち・照合除外を損失に含めない。着順だけで展開の正しさは認定しない。結果は公開日別配信に基づき、公式原本との独立照合は行っていない。

累積値は保存全件から再構成するため、再実行で二重計上しない。画面上の手動予想や更新後の再計算はこの評価とは別。モデルやルール変更後も1レース1保存で重複を防ぎ、モデル別集計で分ける。モデル係数や選択ルールの自動変更・自動購入は行わない。

状態の確認：`data/routed_history/status.json` の `last_result_attempt_at`（最後に照合を試行した時刻）、`last_result_complete_at`（最後に照合枠を完了した時刻）、`last_result_check`（対象日・結果待ち数・配信状態）、`last_result_slot`（完了枠）を確認する。`routed-results.html` の最終更新欄にも、予想保存と結果照合の状態を別々に表示する。未完了でも Actions は正常終了できるため、照合済みレース数と `last_result_check.state` を合わせて確認する。照合の対象は発走前に固定した予想だけで、予想本体は結果で変更しない。

動作確認：`node tests/routed-daily.test.cjs`。手動実行：Actionsの当該ワークフロー → Run workflow。ソースの収集エラー・対象数は `data/routed_history/status.json`、評価データは `evaluation.json`。失敗したActions実行自体も確認すること。

実績画面はGitHub上の最新データを優先取得するため、データ保存のたびにPagesの再配信を必要としない。取得できない場合は配信済みの同一サイトデータに切り替え、最終更新日時を表示する。
