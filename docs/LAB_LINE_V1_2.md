V1.1のライン単位探索・6局面・対抗反応を継承し、以下を追加する。既存LABの予想コード、評価データ、保存予想は変更しない。

## 予想と結果の分離

評価処理からエンジンを呼び出さず、保存された`out`を使用する。発走前保存が存在しないレースの予想は追加しない。着順が合っても、途中の戦術仮説が当たったとは認定しない。結果は選手特性・係数・判断理由へ自動反映しない。

対象条件は、出走表公開時刻 ≤ 入力時点 ≤ 生成時刻 ≤ 保存時刻 < 発走時刻。新規保存は出力SHA256も記録し、変更された出力を対象外にする。入力SHA256、発走時刻、レース識別子、選手ID・名前・車番の一致を検査する。不整合・発走後保存・再計算は集計対象外。結果待ちと対象外も別々に表示する。

`data/line_evaluation.json`は公開集計であり、予測確率や購入価値ではない。開始時点でLINE自動保存記録はリポジトリに存在しないため、照合実績は0件。過去の動作例を実績へ転用しない。既存保存の公開範囲は拡張しない。iPhoneの端末保存は別ボタンで既存の結果データと照合できる。端末記録は外部へ送信せず、共有集計と合算しない。結果未配信は結果待ちのまま残す。

## 判断の逆転条件

各軸の重みを変えたとき、全ての生成済み有力候補を再順位付けする。別に、他軸の重みを固定して本線と各候補が同点になる境界を計算する。後者は2候補間の境界であり、全候補の首位交代を保証しない。候補生成や選手特性の再シミュレーションとは表示を分ける。

## 買い目点数

本線・比較差0.35以内の整合的な別展開から、決着評価済みで理由のある3着候補を採用する。比較差の閾値自体は未校正であり表示する。点数を埋めず、採否理由を保存する。有限探索・表示対象仮説の制限は引き続き存在する。

## 検証と実行

```sh
npm run test:line
node scripts/line-evaluate.cjs
node scripts/line-checks.cjs
# HTTP配信とPlaywright Chromiumが必要
node tests/line/browser.cjs
```

同じ保存済み7車・9車入力の再計算要約は`reports/line/v1.2-checks.json`。V1.0・V1.1の保存出力は維持する。旧LABとの画面比較も同一の発走前入力で継続する。
