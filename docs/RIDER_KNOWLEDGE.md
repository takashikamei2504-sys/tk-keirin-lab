# 展開仮説の選手資料庫

全現役S級を対象に、既存の公式名簿・近況成績・公開記事・開催コメントを登録番号で集約する。`riders.html` の各選手に資料と不足項目を表示する。

## 収集する20項目

S取り・前受け、突っ張り・主導権、引き・立て直し、カマシ・加速、捲り・仕掛け時機、位置取り・競り、追走・千切れ、援護・牽制、差し・直線、持久力・末脚、単騎・自在・番手自力、師弟・信頼・連係、地元・役割・意欲、調子・疲労、落車・欠場・復帰、練習・調整、自転車・機材・ギア、バンク・風・走路適性、日程・競走条件、経歴・競技経験。

`scripts/rider_knowledge.py` は本人確認済みの発言欄、または本文の単独フルネーム主語から話題を検出する。否定・仮定・意向も原文の意味を残して記録し、話題があることを能力の実測や肯定の事実とみなさない。本人以外の動作が発言中に含まれ得るため、新規の話題記録から行動スコアは生成しない。既存の厳格な行動観察抽出は引き続き別処理。

## 出典と履歴

出典URL、掲載時刻、初回取得時刻、発言者の照合方法、種類、短い根拠、開催の識別子がある場合はそれも残す。記事本文の保存はしない。新規話題記録の抜粋は選手・記事あたり合計160文字、1記録80文字まで。採用タグは保存した抜粋の範囲で再検出する。登録番号が矛盾する記録、同姓同名で一意に照合できない記録、未来・日付不明・本文未確認は資料庫に採用しない。

`data/rider_dossiers.json` は取得済み資料の索引。`recent_form` は最新の公式集計（元スナップショットID付き）、`race_cards` は期間を混ぜないS/B観測履歴、`notes` は観察・本人コメント・連係発言・話題記録・開催コメントを区別する。既存のライブ記事・出走表の保存期間を超えても、資料庫の取得済みノートとS/B履歴は残す。現役S級名簿から外れた選手の過去版はGit履歴に残る。

## 自動更新

既存の記事収集ワークフローに集約処理を追加。日本時間06:20・12:20・18:20（GitHub側の遅延あり）に記事・出走表収集後、資料庫を再構築して保存する。近況は従来どおり2時間ごとで、資料庫は次の集約時に取り込む。記事の持越しURLを優先し、確認済みリンクから記事一覧の続きを予算内で探索、未探索一覧も持ち越す。新抽出器で未解析の既存記事も再取得対象にする。失敗URLには3〜72時間の再試行待ちを設ける。robots、取得間隔、時間・件数上限、課金なしの条件を継続する。

## 限界と予想への利用

20項目は収集の分類であり、全媒体・全発言の取得完了を意味しない。6媒体の既存収集元とKEIRIN.JPの公開資料が範囲。公開日や発言者を確認できない記事、有料・非公開資料は対象外。情報のない項目は未取得として残す。所属や成績から、師弟関係・追走力・風への強さ等を創作しない。

追加資料は既存の買い目・エンジン係数を変更しない。行動観察は従来の発走前時点・局面条件の照合を通じて使用する。新規の広い話題記録は資料庫に保存し、数値補正や学習済みの特性であるようには扱わない。予想に利用するときは集約時刻ではなく、各原記録の掲載時刻と初回取得時刻を確認する。

検証：`python3 -m unittest discover -s tests -p 'test_*.py'`、`npm test`、`node tests/s-riders-browser.cjs`（Chromiumが必要）。
