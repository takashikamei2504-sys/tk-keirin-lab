# B-AXIS v0.5｜ちぎり・ちぎられ・突っ張り・カマシ・単騎の公表統計検証（2026-11-08）

## 結論

**実際に存在する選手別公表指標を発見したが、個別EX数値の機械可読な全数取得は未成立。** 数値が得られたものだけを使う、発走前時点・出典・分母付きの入力アダプタを実装した。EXの数値未取得は「0%」ではない。

公開の日別出走表と確定着順で直接数えられる位置別成績は、139日・男子7/9車の2,091Rから更新。選手別の単騎・ライン先頭・番手・3番手以降の着順を1,908名分（各該当役割3走以上）保存した。

EXは11区分。かまし成功率、つっぱり成功率、ちぎり率、ちぎられ率、飛びつき成功率、競り勝率、ライン位置別、レース種別、周長、天候、時間帯。

### 重要な区別
| 指標 | 必要な実測 | 代わりに着順で計算できるか |
|---|---|---|
| ちぎり率 | ライン先頭として走った機会、後続を千切った回数 | **不可** |
| ちぎられ率 | ライン後位として走った機会、先頭に千切られた回数 | **不可** |
| 突っ張り成功率 | 突っ張りの実際の試行と成功数 | **不可** |
| カマシ成功率 | カマシの実際の試行と成功数 | **不可** |
| 単騎勝率 | 事前単騎として出走した回数と1着数 | **可** |
| 単騎3連対率 | 事前単騎の出走回数と1〜3着数 | **可** |

EXはあくまでもWINTICKETが独自に判定した事後の戦術観測。選手が単騎で勝ったからカマシが成功したと逆算しない。勝者がB選手・Bラインに限るという仮定もしない。

## 実装内容
- \`js/b-axis/ex-data.js\`：EXの観測値 \`events/opportunities\` を取り込む。実際のWINTICKET出典URL、取得日時、発走前截止、観測期間、正しい分母が揃った値だけ受け付ける。データ欠損や矛盾率は棄却。試行が少ない場合は事前率へ縮小して極端な補正を避ける。
- \`js/b-axis/follow.js\`：実測EXがあれば、現ライン先頭の「千切り」と各後位選手の「千切られ」を、**直前の車輪への追走**と区別して小幅調整。戦術的に飛び出した前の選手を正しく評価。実測EXがなければ従来の脚力・得点差を使用し、数値を埋めない。
- \`js/b-axis/engine.js\`：実測カマシ・突っ張り成功のサンプル数が十分な場合のみB候補の支持度を微調整。**成功率 ≠ その戦法を選ぶ頻度**と区別。単騎の実測勝率・3連対率と139日の位置別成績を、小さく終盤着順へ反映する。
- \`scripts/b_axis_aggregate_role_history.cjs\`：個人別の\`solo / leader / second / thirdPlus\`実績を保存。フィードの時点とレース日を照合し、将来の情報を過去に注入しない。
- \`data/b_axis_ex_observations.json\`：スキーマ・原典の案内のみ。**個別EX観測値は現時点0件**。空だからといって千切られゼロとしない。
- iPhone UI：v0.5研究版と凍結v0.2を切り替え。公開ソロ／番手等の実績の分母と3連対を表示。EX元数値は取得できている場合だけ表示する。

## テスト
- カウント整合性を確認したEXサンプル値（テストで作った架空の検証用フィクスチャ）は予測結果の追走間隔を変え、古性の追走関係を変えても選手消失・B条件破綻しないことを自動検査。
- EX観測の時刻が発走後、分母なし、率と回数の矛盾、他ドメインである場合、計算の対象外とする。
- 四日市GIII近畿8-3-5ラインの古性が寺崎に追走できる基本シナリオは維持。
- 2026-11-06の実測B26R回顧（当時の凍結出走表、モデルは後から開発）では、Oracle Bを与えた上位3/5/8/10点はv0.5で7/10/13/14R、凍結v0.2で7/10/11/14R。AIがB選択する通常方式の5点はv0.5 8R、v0.2 9R。**新方式の優位性は未証明**で、引き続き旧版を画面の初期モデルとする。

## 残課題
1. WINTICKET公開画面で選手別の実際の分子・分母を公開APIか許諾された取得方法で取り出せることを確認する。
2. かまし・突っ張りの**使用頻度**と成功率を別々に蓄積（成功率だけでは予想戦法は決められない）。
3. 千切り／千切られの実測母数、ライン相手、日付、競走格、7/9車を照合し、選手コンビの相互作用を検証する。
4. 公表EXを入れた状態の未来側未見レースで三連単5点・10点を評価し、5点で改善した方式のみ採用する。
