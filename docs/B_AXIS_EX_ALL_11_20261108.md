# B-AXIS v0.6｜EXデータ全11分類の反映状況と独自の条件別実績（2026-11-08）

## 目的・結論

WINTICKET公式のEXデータ11分類を、B獲得・戦法・追走・番手奪取・順位予測まで取り込む構造へ変更した。ただし、**11分類すべてのWINTICKET公式数値を取得できた、という意味ではない。** 戦術6分類は本人別の元数値を発走前に確認できた場合のみ取り込む。条件5分類は公開出走表と確定結果から**別の独自集計**を構築し、公式EXとは明確に区別する。

WINTICKET公式資料（定義・戦法の注意点）：https://www.winticket.jp/keirin/column/ex_data （2026年1月29日付）

## 時系列ホールドアウト（3着以内の評価）

公開結果の個人×条件別の3連対率を小標本補正して、条件グループの平均3連対率と比較。指標はBrier誤差（**小さいほど良い**）。各軸で異なる集計対象数を使い、個々の選手が複数カテゴリに重複登場するため、各行を統合した三連単精度を示すものではない。

| 区分 | 条件グループの平均 | 個人×条件補正 | 差（改善） |
|---|---:|---:|---:|
| 位置別 | 0.241271 | 0.240939 | +0.000332 |
| レース種別 | 0.238327 | 0.238276 | +0.000051 |
| バンク周長別 | 0.244210 | 0.243907 | +0.000303 |
| 時間帯別 | 0.244295 | 0.244133 | +0.000162 |
| 天候別 | 算定不能 | 算定不能 | 観測不足 |

改善幅はごく小さく、**これだけで将来の三連単的中率・回収率が上がったとは評価できない。** 時系列分離後も元データの保存時点の完全な再現はできないので、実戦の検証は別途必要。

## 設計・検証の安全条件

1. B選手≠勝者、Bライン≠必勝。EXは戦術と位置別相互作用の判断材料として使い、全選手を着順候補とする。
2. カマシ／つっぱりは**成功率（試行条件付き）**と**試行頻度**を区別する。公式に試行機会が確認できない数値で「その選手が必ず突っ張る」などとは断言しない。
3. 千切り率は**ライン先頭**、千切られ率は**各後位選手**に対応。Bからの累積距離と直前車輪への追走を混同しない。
4. 飛び付き・競りの勝率は、他ラインとの接近や番手位置の物理的条件が成立するときだけ評価する。実測値がなければ未校正の相対指標にとどめ、独自の「成功率」を捏造しない。
5. 位置・種別・バンク・時間帯の独自履歴は **データ最終日よりレース日も発走前スナップショットの日本日付も後**の場合に限り利用する。11月7日の結果を11月7日の予想へ混入させない。
6. 天候の値が公的記録として得られていない場合は欠損として扱い、降雨率などを推測して加点しない。
7. 少数出走の個人条件別3連対率は、同条件の集計平均に縮小して過学習を抑える。各指標の重複による過大加点を上限で抑える。
8. モデル研究版v0.6はiPhoneで切り替え可能とし、v0.2を初期選択に維持する。EX全11分類を開いた時に**公式元値・独自集計・未取得を区別**して表示する。

## 実装・再現

- \`js/b-axis/ex-data.js\`：公式数値の6戦術＋5条件別 \`wins/top3/opportunities\` の検証。
- \`js/b-axis/ex-context.js\`：公式元値優先、なければ独自結果の5条件別実績を補正。天候欠損・時点チェック。

- \`data/b_axis_ex_context.json\`：iPhone用の簡潔な条件別実績。約0.8MB。

- \`scripts/b_axis_ex_context_aggregate.cjs\`：元出走表・結果から再作成。
- \`scripts/b_axis_ex_context_validate.cjs\`：時系列ホールドアウト。
- \`tests/b-axis-ex11.test.cjs\`：公式元値型の架空テストデータのみをテスト内で使用して11分類の機能確認。**架空数値は本番データへ一切書き込まない**。
