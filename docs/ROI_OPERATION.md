# ROI ENGINE 運用

iPhoneでは `roi.html` の先頭にある「本日の購入対象」だけで買い目を確認できます。0レースなら見送りです。展開の研究候補は折りたたんで表示し、購入対象には数えません。各買い目100円、最大10点。購入の代行は行いません。

## 購入判定

1. 保存済みLAB・LINEから独立した展開根拠を統合。過去の予想を変更しません。
2. 学習300R、直近の時系列検証200RでLog LossとBrierを一様予測と比較。分割は初期2026-11-06、その後は当日0時JSTの7日前を境界とします。結果取得時刻も境界より前であることが必要です。
3. 上記を通過した時点から固定保存した確率を、7車・9車別に新規200R・14日以上評価。日単位の誤差を考慮し、Log Loss・Brier双方の改善下限が正の場合に次へ進みます。研究時の再計算値をこの発走前検証に代用しません。
4. 確率帯ごとに1レース1票を選び、100R・期待的中5件以上からWilson下限と予測平均の比を算出。実績のない確率帯は購入対象にしません。この下限は推定誤差への保守的補正であり、利益の保証ではありません。
5. 三連単確率×実オッズ×上記の下限係数×0.90が1.20以上なら候補。1.10・1.30も同じ取得オッズで並走評価し、結果を見て本番閾値を変更しません。

## オッズと判断の固定

WINTICKETのログイン不要の公開レースページを使用します。`FETCH_KEIRIN_RACE_ODDS` の三連単値、`oddsUpdatedAt`、`finalOdds`、`oddsDelayed`とレースの締切を照合します。画面の相対スコア、確定払戻、HTTP取得時刻をオッズ更新時刻の代用にしません。210/504通りの完全性、車番・選手登録番号・氏名・開催日・場・R・発走時刻も照合します。

2026-11-07に公開ページの形式、利用規約 https://www.winticket.jp/terms 、robots.txtを確認。robotsは `/keirin/cups/` を対象外としており、本処理はracecardの公開ページのみを取得します。非公開API・ログイン・制限回避は使用しません。取得成功は再配布許諾を保証するものではなく、仕様やアクセス制約が変われば取得を停止し、見送りにします。

GitHub Actionsは5分間隔の起動を予定。各回、発走5〜15分前の保存済みレースだけを取得。最初に観測した「発売締切2〜8分前」の有効オッズで1回だけ判断を固定します。オッズが欠ける、古い、遅延、確定、選手不一致の場合は採用しません。自動取得の起動・公開には遅延があり、全レースを必ず配信できる仕様ではありません。

予想は `data/roi/forecasts/日付/`、後から取得するオッズと判断は `data/roi/decisions/日付/` に別保存。両者をSHA256で結び、既存ファイルは上書きしません。画面ではオッズ更新から5分、または発売締切の早い方で購入表示を失効させます。

既存LINE評価Workflowで日々再校正・予想保存・結果評価。別の軽いWorkflowでオッズと購入判断を固定します。どちらも自分が更新するデータを起動条件に含めず、内容が変わらなければコミットしません。

購入候補の収支は実際の個人の購入履歴ではなく、発走前固定の候補を各100円で買った場合の実払戻評価です。新モデルの回収率改善は、今後の実レースで別途確認します。
