## 展開ストーリーを主役に（v4.0）

公開画面を、並び・S取り → 赤板 → 最終ホーム → 最終バック → 3～4コーナー → 直線の6段階で語る構成に変更。本線の一つのストーリーを先に選び、その流れから6点、判断が変わる4つの別筋から1点ずつ、計10点を選ぶ。詳しくは[展開ストーリーの仕様](docs/STORY_FIRST.md)。

期別・級班・得点・登録地と、本文で確認できる援護・師弟・信頼の発言を分離する。東スポの公開出走表からSと選手別コメントを自動収集し、先輩や地元を連れることによる意欲は推測と明示する。未取得の人間関係は創作しない。S資料がない場合も実測ゼロに置き換えない。現在は未校正のルールによるストーリー生成であり、精度の向上はこれから検証する。

各段階で、実際に選択肢の重み付けに使った材料・推測・別の判断を開いて確認できる。当日の先行・捲り等の意思、近況B、位置、消耗を局面の選択に接続する。追走先・単騎コメントで並びを照合し、競りや矛盾があれば確認を促す。

本線は、分岐確率を掛けた一本の経路の重みだけでは決めない。ホーム・バック・3〜4角で各選手の仕掛けと待機を比較し、反撃・番手の応答を検討した候補から選び直す。最終バックにも新たな仕掛けと主導権の変化を生成する。仕掛けるべき別線を止めたままの展開、外の有力な仕掛けを処理しない展開は本線の採用対象外。未校正の比較規則と限られた探索であり、実際の最適判断や実測確率を保証するものではない。

## 結果の自動照合・評価

画面下の「レース結果・予想の評価と改善」で、配信された着順・同着・3連単払戻と予想の成績を確認する。`collect-outcomes.yml` が毎時27分・57分（GitHubの遅延あり）に当日・翌日と直近6日分の公開日別データを取得する。近況・記事収集の成功後にも予備経路で起動する。画面には起動元・最終定期成功時刻を表示し、90分以上更新がなければ遅延を表示する。配信更新が翌朝になる場合があり、結果未取得は結果待ちとして扱う。男子7車・9車が対象。配信結果は公式原本との独立照合前であり、その旨を画面に表示する。

発走前かつ出走表の生成時刻が発走前の場合だけ、独立エンジンと旧エンジンを同じ入力で実行し、各バージョンの最初の共通予想を `data/lab_history/日付.json` に固定保存する。入力、利用した記事根拠、入力とエンジンのSHA256、買い目と対応展開、各局面の判断根拠、全候補の順位、新旧の同じ点数の買い目を保持する。過去レースの予想は後付けしない。出走者・発走時刻が変わった記録は評価から除外し、事前記録のない終了済みレースは結果だけを表示する。

評価は1レース1回。同着の有効組合せのどれかが20点にあれば的中。1着候補・1／2着の組合せ・3着候補の漏れ、モデル内の決着順位、新旧の同一対象比較を集計し改善候補を抽出する。着順から追走離れ等の実際の展開を断定せず、結果だけで選手特性やモデル係数を書き換えない。払戻表示は実際の購入収支を表さず、回収率・確率校正はまだ評価しない。

端末では発走前に最後に表示した予想を別に自動保存（最大300件）。発走後の再描画で上書きしない。共通予想と端末記録は区別して照合し、評価記録のJSON保存に対応する。端末記録はSafariの保存領域・時計に依存するが、共通記録はGitHubに残る。追加の有料API・サービスは使わない。

検証: `node tests/results-audit.test.cjs`、`node tests/results-browser.cjs`。手動収集: `python3 scripts/collect_outcomes.py --days 7`。

## 逐次判断エンジンを接続（v2.0）

[実装仕様](docs/NEXT_BRAIN_IMPLEMENTATION.md)。`js/race-brain-v2.js` をv1.4画面へ接続し、相手の動きに応じた判断とその結果を順に生成する。前受けからの突っ張り／引き、仕掛けの成功／不発、追走、空き番手、終盤の複数の動きを検討する。重みは各分岐で正規化し、全決着を集計して20点を選ぶ。説明の経路数で評価を増やさず、探索打切り分は詳細表示とJSONに残す。

本文記事は発走前の公開・初回取得と局面条件を検査。行動観察と本人コメントを分け、意向や調子を恒常的な性格にしない。キーマンは同じ判断前の状態から下流の反応を比較する。進路・速度・車間・消耗は未計測／仮説として表示し、校正済み的中確率とは扱わない。買い目は従来どおり20点、同じ1・2着はまとめて表示する。

`npm test`・`npm run prepare:next-brain` で新旧エンジンと基準維持を検証。旧 `js/race-brain.js`、従来v1.2、元v1.3を保持する。課金APIや有料サービスは追加しない。

## 今回の実装

v1.3の画面を基に、別ファイルの独立エンジン `js/race-brain.js` を接続。従来のAI印・買い目・手入力の人物仮説・特定選手の固定シードから独立して生成する。

- 公開記事本文をPython標準ライブラリだけで自動収集。東スポ競輪・KEIRINスポニチ・netkeirinの公開一覧から記事を発見し、本文・公開日時を検査。記事見出しや検索スニペットは特性の根拠にしない。
- 当日・翌日の公開出走表から選手名簿を自動構成。本文中の明示的な単独主語から、前受け・突っ張り・引き・カマシ・追走・番手はまり・再自力・差し・大外の観察を抽出。複数選手の混在、否定・仮定、日付不明、取得不可は採用せず状態を記録。
- 選手特性は記事観察と脚質・得点等の暫定値を統合。単一記事を恒常的な性格と断定しない。古い情報は減衰し、同じ記事の重複で強化しない。
- 周回→打鐘→最終ホーム→最終バック→直線の隊列と消耗を保持。離れで空いた番手は近くの別線が利用し、再自力は追走喪失→後退→外への仕掛けとして生成。
- 他の条件を揃えた対の判断分岐からキーマン3人を抽出。3連単は重複なし20点。上位16点に番手はまり・再自力・大外等の別筋を追加する。
- 記事根拠・情報不足・出典・公開／取得日時を画面に表示。レース切替で再計算。20点コピー・JSON保存に対応。

## 自動更新・費用

`.github/workflows/collect-intelligence.yml` は日本時間06:20・12:20・18:20に最大60記事を収集（GitHubの混雑で遅延する場合あり）。初回pushと手動実行にも対応。公開リポジトリの標準GitHub ActionsとPagesを使い、課金API・新規有料サービス・APIキーを使わない。リポジトリ／組織側でActionsを無効化している場合は実行されない。

収集はrobots.txtを確認し、サイトごとの間隔と記事数・時間を制限。本文全体は保存せず、短い根拠と出典だけ保存する。ログイン・有料記事の回避はしない。サイトの構造変更等で失敗した場合は既存の根拠を保持し、収集状態を更新する。

## 近況成績の自動収集（追加）

`collect-recent-form.yml` が2時間ごとに公式の全現役S級名簿と当日・翌日の男子7車／9車出走表から登録番号と氏名を取り出し、KEIRIN.JPの公開プロフィールを自動取得する。各回最大1000人・18分の収集予算、ホスト全体で開始間隔1.05秒以上・同時最大3件。既取得選手は8時間キャッシュし、不足選手を優先して順次補完。取得上限・サイト遅延等で未取得の選手は次回へ持ち越す。ログインや課金APIを使用しない。

取得内容は直近4ヶ月の1〜3着・着外・棄権・失格・総出走回数・勝率・2連対率・3連対率・B回数、および最近20開催の着順。画面には最近5開催と、今開催の確定済み着順を分けて表示する。開催日は初日であり、各着順の競走日を推定しない。S回数はこの資料にはないため未取得のままとする。

`data/recent_form.json` に公開資料の更新日時と初回取得日時を持つスナップショットを45日間保持。同じ観測は初回取得日時を変更しない。登録番号と氏名の一致、列名、数値・着数と率の整合性を検査し、不一致は未取得扱いとする。履歴の棄権・失格は数値の最下位着へ置き換えない。

v1.4は読込時に近況データも自動取得する。「自動収集した近況成績」で選手別に確認できる。発走前に収集済み、資料更新から発走まで72時間以内のスナップショットだけ独立エンジンへ反映。過去レースに後から収集した集計は流用しない。資料の3連対率は差し脚と能力評価に小幅反映する暫定ルールであり、学習済み・校正済みではない。旧v1.2／元v1.3は維持。

検証: `node tests/recent-form.test.js` と `python3 -m unittest discover -s tests -p 'test_*.py'`。


## 出走予定に関係なく全S級を収集

公式の選手検索（現役・男子・S級）を全ページ取得し、検索結果の総数・ページ番号・重複なしの登録番号数・級班を照合して `data/s_riders.json` に保存する。名簿は原則24時間ごとに更新。ページ取得が欠けた場合は完全取得と扱わず、前回の完全名簿を保って更新エラーを表示する。人数は固定せず、公式検索の現在の結果を分母とする。

近況収集の通常実行と定期実行は、全S級名簿に当日・翌日の出走者を併合する。出場予定のないS級も全員対象。未取得のS級、未取得のSS班を先に収集し、その後古い記録を更新する。元のA級出走者の自動補完も継続。収集はホスト共通の間隔制限と時間予算を守り、未完了分は次回へ繰り越す。名簿の完全性とデータ取得率は区別する。

`riders.html` は全S級データ画面。氏名・登録番号・府県・級班で検索でき、近況の取得済み人数／未取得人数、級班別の網羅率、出典・取得日時を確認できる。データのない選手を一覧から消さない。記事収集の選手名簿にも全S級名簿を加え、出走者だけに限定しない。


## 局面別判断と幅広い展開候補（v1.4.2）

押し切り・番手差し・番手はまり・再自力・大外強襲に、引いて捲り返し、第三ラインの捲り、仕掛け不発時の番手切替、追走を保った3番手の追込み、単騎の追上げを追加。並び・前段の攻防・位置・消耗に応じて候補を生成する。再自力など特定の型を必須採用にはせず、20点の上位16点と残り4点の別筋を仮説スコア順で選ぶ。並びに第三ラインや単騎がない場合、その展開は生成しない。

近況のB回数を出走数で割り、少数出走を縮小補正して主導権・カマシの傾向へ小幅反映。3連対率は直線評価に使用。これらを前受けや追走力の実測とは扱わない。記事観察と暫定値の区別を保ち、各展開の局面別判断根拠、各買い目の採用理由と対応経路を画面・JSONに含める。キーマン比較では、追走の判断を比べる場合のみ主導権の帰結を揃え、突っ張り・仕掛けの判断では主導権が変わる効果も含める。各型の係数・採用枠は未校正の設計であり、的中確率や期待値ではない。


## 公開記事の収集先拡大（v1.5）

東スポ競輪・KEIRINスポニチ・netkeirinに加え、オッズパークの選手インタビュー、楽天Kドリームスの開催別選手インタビュー、けいりんマルシェの選手コラムを収集対象にする。トップ・記事一覧から観測したリンクだけを辿り、過去のインタビュー一覧・開催ページも1回最大8ページ探索する。各媒体を交互に処理し、1媒体だけで収集枠を使い切らない。最大60記事・8分を予算とし、未完了URLを次回に持ち越す。課金APIは使わない。

オッズパークは記事題名のフルネームと発言者ラベル、Kドリームスは選手見出しと同じコメント欄を照合。質問者・別の選手の発言・題名だけの推測は採用しない。本人の意向・調子・練習等の短いコメントは `observations` に保存し、実際の走りの観察 `evidence` と分離する。コメント全体を特性スコアに変換せず、完了した本人の動作だけ保守的に観察として抽出する。原文全体は保存しない。

掲載日不明・未来日・本文未取得は情報不足として記録。日付しかない記事は日本時間の当日末を採用し、発走前に使えると断定しない。robots.txtの取得失敗・403・429・サーバエラーでは収集を止める。404/410はRFC 9309の unavailable として扱い、200応答では解釈可能な規則を守る。

全S級選手一覧に媒体別の今回の本文取得数・保存コメント数・未取得数と、選手ごとの本人コメント・原記事リンクを追加。近況成績の取得率と記事コメントの網羅率は区別する。新しい収集元の追加だけで全S級の性格が把握できたとは扱わない。


## 予想を中心にした画面構成

主画面はレース選択→展開予想と対応買い目→3連単20点の順にする。買い目ごとの採用経路を、前受け・仕掛け・主導権・追走・決着筋が一致するグループにまとめ、20点一覧の「展開番号」から該当する説明に戻れる。最初は3案を表示し、他の案と隊列の詳細は必要に応じて開く。買い目の重みや20点の選び方は変更しない。

出走選手・並び・近況、キーマン、記事根拠、取得状況とJSON保存を下部の折りたたみに移す。旧モデルの複数の予想画面は「旧モデル・研究用の画面」内にまとめる。v1.2・元v1.3はそのまま残す。画面整理は `scripts/layout_page.py`、表示上の展開と買い目の対応付けは `js/prediction-view.js` が担当する。


### 買い目のまとめ表示

展開ごとの買い目、20点一覧、コピーでは、1着・2着が同じ買い目を3着でまとめる。例：1-2-3／1-2-4／1-2-5 → 1-2-345（3点）。3着は車番順に並べ、表示行数と実際の点数を区別する。20点の選定とJSON保存内の個別買い目は変更しない。異なる展開に由来する買い目が同じ行に入る場合も、各買い目の展開リンクと採用理由を保持する。
