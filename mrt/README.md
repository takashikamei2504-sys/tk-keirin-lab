# Mr.T研究 V3 / 手動Bライン

`mrt.html` が男子7・9車の自動／手動Bライン画面。ホームとLAB LINEから移動できます。既存エンジンのモデル・買い目は変更しません。

採用中V3（学習7,126件、履歴2026-11-21）を使用。重みSHA256：`2704d1ce9964a3365507595b70174dfc81959e8fc3009dbac4bdb98553454b2b`。V4研究候補には切り替えません。保存済みモデルの読み込みのみで、配信時の再学習はありません。

## 配信

```sh
pip install -r mrt/requirements.txt
python -m mrt.publish
python -m mrt.results
```

日付指定は `python -m mrt.publish --date YYYY-MM-DD`。履歴日以前と締切後の新規予測生成を拒否。公開一覧の競輪場タブで実際に掲載されたレースURLだけ取得し、HTTP 401/403/429で停止。1秒以上のリクエスト間隔、25秒タイムアウト。先生の印・記事・現在レースの結果は特徴量にしません。

一般出走表の正規URL、タイトルの日付・場・R、車番と登録番号の重複、得点・脚質、並びの全車一致、発走／締切時刻を検査。ガールズ、並び欠損、欠車等の不整合は利用不可。未確定の単騎を創作しません。

自動と既知各ライン×2方式を1万円で事前計算。先頭車B固定（標準）／指定ライン内のBウェイト再配分を選択。B条件は1着やライン独占を固定しません。全三連単候補からV3の条件付きスコアで選び、従来と同じ配分を使用します。スコアは校正済み的中確率ではありません。

`data/mrt/日付/レースID-指紋.json` は生成済み予測・完全入力・モデル／コードSHA・取得／生成／締切時刻を持つ不変スナップショット。`index.json` は毎回の再確認状態。出走者・並び・時刻変更は新入力として扱い、エラー時は古い予測を現在のものとして表示しません。予測未配信の終了レースに後付け予測を作りません。

GitHub Actionsは毎時04分・34分（遅延あり）に配信・直近7日照合。定期処理では推論／検査のみ。ソース変更時は加えてモバイルブラウザテストを実行します。公開リポジトリの既存Actions/Pagesを使用し、課金サービスは追加しません。

## 端末保存と結果

ブラウザは条件ごとの計算済み結果を切替表示。指定条件を解説・JSONに含めます。条件／レース変更時は以前の結果を消し、明示的な生成操作後にだけ表示・保存します。自動／手動ライン／B取得者ルールごとに最初の締切前表示を固定保存。入力指紋とエンジン指紋も保存キーに含め、再描画で上書きしません。

最新の入力確認から75分を超えた場合と締切後は参考表示のみ。端末時計・Safariの保存領域に依存するため、サーバーによる手動選択の発走前証明ではありません。サーバーに保存される各条件の計算候補と、利用者が実際に端末で選んだ予測は区別します。

結果は正規URL、発走時刻、車番別の登録番号と三連単払戻を照合。同着は払戻組合せで計算。欠車・失格・棄権など不規則な結果や未確認資料は対象外／結果待ちとして扱い、不的中に置き換えません。端末で自動・各手動条件を分けて仮想回収率を集計。手動指定の優位性は未検証です。

## Mr.T本人の事後公開予想を継続収集

`python -m mrt.teacher_daily` が2026-11-22以降の本人予想を `data/mrt_teacher/` に追加します。専用workflow `mrt-teacher-daily.yml` は日本時間00:20・03:20・07:20（GitHubの遅延あり）に実行。対象の末日は原則として前日（開始当日だけは当日の終了待ち）、通常は直近7日、毎月1日の実行では31日を再走査し、既知の未完了予想IDは通常の期間を過ぎても再確認します。手動再取得はworkflow_dispatchのdate/lookback、または `python -m mrt.teacher_daily --date YYYY-MM-DD --lookback 7`。

全国の公開レース一覧を競輪場タブまで取得し、全レースの発走予定時刻がそろうことを確認。最終発走15分後までは本人の予想詳細を取得しません。その後、全レースの結果確定（または明示的な中止）を確認してから、本人の公開一覧に掲載された `b…_634` のみ取得します。予定時刻を過ぎただけで終了・公開済みとは判定しません。未公開の買い目や見解、ログイン・購入先への転送、HTTP 401/403/429は回避しません。

保存内容は、本人の予想ID・レースID、券種別買い目と金額、印と公表並び、解説から自動抽出した選手別行動・否定・条件分岐ラベル、実際のB/S・着順・決まり手・上がり・払戻、出典・応答ハッシュ・初回取得時刻です。本人ページの着順・購入額・収支と、別の結果ページの着順・払戻を照合。返還は購入額からの控除として扱い、払戻に二重加算しません。同じ提供者内での照合であり、主催者原票による独立保証ではありません。

`records/予想ID.json` は初回の正常取得を固定保存し、再実行で重複・上書きしません。`results/レースID.json` と結果修正版、`days/日付.json`、`status.json` を保持。既知の公開待ち・照合待ちを翌日以降に再試行し、公開一覧が空でも「予想なし確定」とはせず再確認します。「公開一覧に現れた全ID」の対応状況を示し、非掲載・削除済み予想を含む独立した全件数の保証はしません。

解説本文は取得時にメモリ上で処理し、公開リポジトリには全文を再掲しません。本文ハッシュ、文字数、出典と現在のV3抽出器による構造化ラベルを残します。これらは事後参照の学習ラベルであり、現在レースの予測入力には使用しません。既存の発走前スナップショットが選手登録番号まで一致する場合は、そのパスも関連付けます。ない場合は未取得を明示し、事後入力を発走前保存として作りません。

画面の「Mr.T本人の公開予想の収集状況」で選択日と累計の保存状況を確認できます。今回の接続で本番モデルの学習・自動採用は実行しません。新しいデータは次回の候補モデル作成と時系列検証に使用します。

検証：全レース終了前の取得禁止、最終結果待ち、公開遅延時の再取得、本人・日付・レースID・金額の一致、再実行の非上書き、空一覧・アクセス制限の明示を `tests/mrt/test_teacher_daily.py` で確認。既存の公開済み25件の買い目・金額・着順・払戻も照合しました。2026-11-22の日中の初回接続では全国68レース・最終発走23:30を取得し、本人予想の取得に進まず「全レース終了待ち」となることを実測確認しています。

## 自動研究・比較検証（本番採用は人が判断）

`mrt-research.yml` が毎日08:10 JSTに `python -m mrt.research` を実行します。結果照合は毎日、直近28日の現行版点検は月曜日、月次候補作成は毎月1日です。1/4/7/10月1日は直近3か月のB取得者押し切り・同ライン別選手・別線決着および解説の行動ラベルを車数・級班別に集計します。GitHub Actionsの開始時刻には遅延があります。初回接続時だけは曜日・日付にかかわらず点検し、初期状態を表示します。

追加の学習対象は、先生本人の公開予想・実測結果が照合済みで、同じ選手登録番号の**発走前入力が保存されている**レースに限ります。入力のない公開予想も先生収集側には残し、研究側は保留件数を表示します。公表印や先生の並びを現在の予測入力として代用しません。元の7,126件は `research_seed.json.gz` とチェックサム付きmanifestに保管。過去に事後取得した一般出走表であり、発走前保存実績とは区別します。全文の見解は含みません。元入力と同じ特徴量になる範囲でコメントを8語の特徴量用トークンに縮約しました。

月次の固定プロトコル：発走前入力がある直近14開催日・100レース以上を検証用に確保し、その**前**の期間で現行モデルの学習期限を超える新規学習対象が100レース以上必要です。検証期間が現行版の学習済み期間に重なる場合も保留。閾値は標本数の最低限の運用条件であり、統計的な改善保証ではありません。条件不足の月は再学習せず、翌月に再確認します。公開予想のない日が挟まっても14開催日を確保できるよう期間を遡ります。処理エラー時は翌日の定期実行でも再試行します。`--force-check` は日次以外の確認を今実行するだけで、データ条件・採用判断は省略しません。

候補はV3の実際に配信で使うB判定・点数・B条件付き1/2/3着モデルを再学習し、解説の行動ラベルモデルも更新します。ハイパーパラメータ探索や検証期間での閾値調整は行いません。使われない旧V2の券種・着順モデルは複製しません。学習終了時点の選手履歴を固定し、検証レースの結果・見解は特徴量にしません。検証期間を含めて再学習し直すことはせず、その候補自体を前向き検証へ送ります。

`mrt.shadow` は既存の毎時04/34分の発走前配信処理に接続。最新候補を現行版と**同じ保存入力・同じ自動B条件・同じ1万円予算**で計算します。両方の計算が締切前に完了した場合だけ `data/mrt_research/forward/候補ID/レースID.json` に最初の比較を固定。締切後の後付け・モデル指紋不一致・入力変更を拒否し、再実行で上書きしません。手動指定Bラインの利用者選択は比較しません。過去入力による再計算と、本当に発走前に固定した予想の成績は別表示です。

**本番自動反映は実装しません。** 全候補と報告に `automatic_promotion:false` / `adoption:human_decision_required` を保存。出力は `data/mrt_research/` に限定し、`mrt/models/v3.joblib` や配信用のモデル選択は変更しません。画面に採用操作や自動切替はありません。比較結果を確認し、候補IDを指定した別途の意思決定後にのみ、本番反映の作業へ進めます。
